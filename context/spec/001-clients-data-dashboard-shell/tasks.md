Spec: `functional-spec.md` (FR1–FR7) · How: `technical-considerations.md` (D-1…D-13, §2.1–2.5, §4) · Reviews: `reviews/TRIAGE.md`.
Four slices, each runnable on its own. Slice 1 is the walking skeleton and carries the riskiest unknowns (R1 contracts-as-source under Vite + Nest + Node type stripping, R2 Nest 12 ESM in a pnpm workspace) — nothing else starts until it is green. Lanes inside a slice run in parallel in their own worktrees; `[Lead]` steps run after the lanes; `[User]` steps are the human's.

## Standing rules

- Read `CLAUDE.md`, then `functional-spec.md`, then `technical-considerations.md`. The tech doc is the contract for versions, file paths, option names and scripts — it was verified by running things; do not "improve" a version or an option without re-verifying and saying so in your ledger note.
- Prefer `type` aliases over `interface`, everywhere (owner's convention). CSS Modules with tokens, no Tailwind, no inline style objects. FSD import direction only downward; every slice exposes `index.ts`.
- Own only your lane's directories (`harness.json → lanes`). A task that needs a file elsewhere → `BLOCKED: needs <path>` in your report, never an edit.
- Tests are written with the change and proven RED first (temporarily revert, watch it fail, restore). Never delete or skip a test to make a gate green. A completion claim cites fresh output from this run.
- Gate before you finish: your lane's `check` script. Not green → `PARTIAL`, with the failure quoted.
- Node `22.23`, pnpm `10.18`, TypeScript `~6.0.3`, Nest `^12.0.4`, Vite `^8.3`, Vitest `^5.0.1`, React `19.3`, TanStack Query `^5.103`, Playwright `^1.63`, zod `^4.6`, ESLint `10` — pin exactly what `technical-considerations.md` §2 lists.
- Every finished sub-task ends with `_(Done <date>: what actually happened, incl. surprises)_` — the ledger future agents read.
