### F1: Retry deadline contradicts the timeout policy
- severity: major
- where: functional-spec.md:FR4 acceptance criterion 4
- problem: Retry must return to the error panel within 2 seconds whenever the problem persists, but a persistent timeout requires two 10-second attempts. Delayed failures also exceed this deadline.
- evidence: FR4 specifies two attempts; `?delay=3000&fail=1` takes at least 6.5 seconds with the configured retry delay.
- fix: Limit the 2-second criterion to immediate failures and explicitly apply the normal timeout and retry policy to manual Retry. Update FR6’s combined-switch timing accordingly.

### F2: Validated child lists can silently disappear
- severity: major
- where: technical-considerations.md:§2.2 TreeNodeSchema and childrenOf
- problem: The schema accepts multiple populated child keys on one node, but traversal uses only the first. Accepted data can therefore be omitted from consistency checks and the future table and chart.
- evidence: A node containing both `branches` and `employees` passes validation; `childrenOf` returns only `branches`.
- fix: Reject nodes with multiple populated child lists, and document that restriction in FR2’s wrong-shape rules.

### F3: The checks gate never builds the API
- severity: major
- where: technical-considerations.md:§2.1 CI and §2.3 API scripts
- problem: CI can pass without verifying the built API boots, copies its JSON asset, or loads the source-exported contracts. These are explicitly identified runtime risks.
- evidence: `pnpm check` runs lint, typechecking and tests; only the web production project builds. The API production smoke is mentioned but has no script or CI step.
- fix: Add an API build-and-boot smoke to `pnpm check:api`, verifying health, the clients response, and production switch handling, then terminating the process.

### F4: Layout stability has no corresponding verification
- severity: minor
- where: technical-considerations.md:§4 loading tests
- problem: The tests mapped to “without the content shifting” only check content, busy state and navigation. They can pass when card positions or dimensions change.
- evidence: FR3-AC2 requires no content shift; the listed browser test asserts “then loaded, no navigation.”
- fix: Compare both cards’ bounding rectangles before and after loading at desktop and 375 px widths.

## Verdict
SHIP WITH FIXES

Resolve the contradictory timing, lossy traversal contract, and missing build and layout checks before implementation.
